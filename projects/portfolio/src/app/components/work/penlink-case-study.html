// System Architecture

Penlink Design System

A comprehensive design system that aligns multiple investigative products under a consistent UI and scalable component architecture.

Role

01. The Challenge

When I joined Penlink, the product ecosystem had evolved as a collection of independent investigative tools with inconsistent UI patterns and interaction models.

Analysts regularly moved between products to complete investigations. The lack of consistency increased cognitive load and made workflows harder to learn.

At the same time, four designers were supporting over 150 engineers across distributed teams in a highly competitive environment where development couldn't slow down.

The challenge was to unify the platform under a shared system without slowing development.

Fig 1. UI Component Audit Pre-System Inconsistencies

Sample from UI audit showing distinct button patterns across the Penlink suite, illustrating the lack of shared constraints and increased cognitive load.

02. Impact

The design system established a shared foundation across the platform, allowing teams to solve interaction problems once and reuse those solutions across products.

This enabled a small design team to support a rapidly growing product ecosystem while maintaining development speed.

03. Approach

Rather than redesigning individual products, I focused on establishing a system that could scale across teams and applications.

The system was guided by three core principles:

// 01

Shared Design Language

Consistent interaction patterns and visual standards across products

// 02

Scalable Development

Reusable components and tokens that reduce duplication and support faster feature development

// 03

Future Flexibility

A foundation that can support new platforms and evolving investigative workflows

This approach allowed the system to grow alongside the platform, providing structure without slowing development.

04. System Foundations

To support a growing product ecosystem, I structured the design system around platform modes rather than individual products, allowing multiple applications to share the same foundation.

At the core of the system is a layered token architecture that separates base values, semantic meaning, and component-level usage. This structure allows design decisions to scale across themes, platforms, and future products without breaking consistency.

Design Tokens

Tokens were structured to translate design decisions into reusable values that could be applied consistently across the platform.

By separating base values from semantic meaning and component usage, the system supports theming, platform modes, and consistent implementation across applications.

06. Design → Engineering Bridge

To ensure the system translated clearly into development, I worked closely with engineering teams to align design decisions with implementation.

I explored workflows that translate Figma component architecture directly into Angular components using AI-assisted tooling.

This experiment focused on reducing friction between design and engineering by aligning system structure more directly with production code.
