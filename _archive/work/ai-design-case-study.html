Exploring how AI-assisted workflows enable design systems to move directly into implementation and extend UX ownership into front-end development.

01. The Challenge

As the primary designer responsible for the Penlink design system, I saw a consistent gap between how systems are defined in Figma and how they are implemented in code.

While components and tokens provide structure in design, translating that structure into production still requires interpretation, creating inconsistencies and slowing development.

As the system scaled across products and teams, this gap became more pronounced. Maintaining alignment between design and engineering required ongoing effort, especially as new features and components were introduced.

I began exploring how the system could be structured not just for designers and engineers, but in a way that could be directly interpreted and consumed by code and AI-assisted workflows.

02. Impact

03. Approach

I explored how Figma component architecture could be structured in a way that more closely aligns with front-end implementation.

This included organizing components, states, and tokens to reflect how they would be built and consumed in code, rather than purely how they are presented in design.

By treating the design system as a source of structured data, I was able to experiment with workflows that translate component definitions directly into Angular component structures using AI-assisted tooling.

This approach shifts the role of the design system from a reference artifact to a system that can more directly inform production.

04. Design → Engineering Bridge

To support this exploration, I worked closely with engineering concepts and implementation patterns to better understand how design decisions translate into production.

The experiment focused on reducing friction between design and engineering by aligning system structure more directly with code, rather than relying on interpretation.

This work represents an early step toward a more integrated workflow, where design systems can serve as both a design tool and a source of truth for implementation.

05. Key Insights

Structured systems enable automation

AI translation was most effective when the design system was well structured. Clear naming, defined states, and consistent token usage improved reliability.

Simpler component architecture produced cleaner and more maintainable outputs.

Speed changes the feedback loop

The primary value was iteration speed.

Components could be generated, tested, and refined in rapid succession. This compressed the feedback loop between design and implementation.

Alignment comes from execution

Generating components directly in code surfaced edge cases earlier and maintained alignment between the design system and production UI.

06. Reflection

This work reinforced a shift in how I think about design systems.

Front-end implementation is part of the user experience—not a separate phase.

By treating design and implementation as a continuous system, the process has fewer gaps and less friction.

I had seen this in practice before, but this exploration provided a clear proof of concept: when system architecture, design, and development are aligned, teams move faster and with more clarity.
